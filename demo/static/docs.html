Rulebook Drift Monitor

Documentation

A governance loop for financial-crime detection rulebooks. LLM agents red-team your typology playbook, quantify how well your indicator rules still catch threats, and let an analyst institute new rules that measurably close the gaps — every loop is measured, reproducible and exportable. This page explains every screen one by one.

Core concepts

  • Drift index (0–100) — how far the live rulebook has drifted from the risk baseline; 40+ is “elevated”, 70+ is “red”.
  • Typology × category matrix — 35 red-team typologies (customer, product, delivery, geography…) against 14 rule categories.
  • Findings — evasions the red team reproduced on real fixtures; an LLM drafts a candidate red flag and the rule engine verifies it.
  • Amendment loop — approve a finding and institute it as a new dedicated rule (DS-41+); the engine self-checks the new rule and the covered typology drops out of the drift measurement.
  • Diffable & exportable — each run is diffed against the previous (NEW / REPEAT / REGRESSED) and a compliance dossier is one click away (JSON + PDF).

Adversarial red-team probe

A live attack simulation built into the console: Run probe.

v nav
…
Adversarial probe · card● Live pill
Run probe button steps panel · what the critic checks for the poisoned claim (payload + over-claimed evasion set) verdict strip · REJECTED · claim not reproducible (red-team)
layout map · run it in the Run Console
  • How it works — hands the platform a poisoned typology: a prompt-injection payload printed through the JSON plus an over-claimed evasion set (more rules than its category can evade).
  • Verification — the engine re-runs its feasibility checks; the steps panel shows exactly what the critic tested for that claim.
  • Verdict — “REJECTED · claim not reproducible (red-team)” when the over-claim does not reproduce. If the injection genuinely bypasses the stack the verdict honestly flips to “FLAGGED · claim reproduced”.
  • Live use — one click, ~1 second, unambiguous result — a strong adversary for the security story.

30-minute demo script

TimeAction
0:00Check-in — show the “Live” pill and the running server; open http://127.0.0.1:5000.
0:02One sentence: “Your indicator rulebook silently rots as real-world typologies change — we make that drift visible and closeable.”
0:03Run Console — point at a finding card: typology, severity, drafted red flag. Accept TYP-001, then Review & institute.
0:06The loop — read the banner back: DS-41 instituted, TYP-001 gap closed; drift KPIs drop (54.6 → 52.9). Differentiator.
0:09Probe — click Run probe; “REJECTED · not reproducible” in under a second; even a prompt-injection payload gets verified.
0:12Dashboard — KPIs, then scroll to the heatmap: severity-sorted rows, green-outlined covered TYP-001, counts in cells.
0:15Forecast — the measured line + projection; the amendment checkpoint bends the curve — the loop is visible in the chart.
0:18Re-run — New run is fast (cached drafting); findings come back REPEAT with the summary diff. Loop is repeatable.
0:22Export — Export dossier (JSON) and PDF; open the PDF and show the amendment table and approved findings.
0:25Reset + Q&A — Reset restores the pristine baseline (40 rules, clean history) — governance and reproducibility.
0:28Wrap — “From a live red-team red flag to an instituted, measured, exportable rule in four clicks — that is the drift monitor.”
