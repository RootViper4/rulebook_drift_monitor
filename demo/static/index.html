Test today's rulebook against today's fraud

A check runs two scans. The first fires fraud patterns that have already been documented at all 40 rules. The second has the system invent fraud nobody has reported yet, and fires that at the rules too.

Anything that gets through is re-tested independently before you ever see it. Nothing changes in the rulebook until you decide it should.

What happens during a check

Four agents work in sequence, and each one's output is checked by the next:

  1. Retrieval loads the current rulebook and the documented fraud typologies.
  2. Simulation runs both scans — known typologies first, then invented ones.
  3. Critic independently re-runs every claimed gap. If it cannot reproduce the result, the finding is thrown out rather than shown to you.
  4. Drafting turns each surviving gap into a plain-English candidate rule.

Whether a rule fired is decided by a deterministic rule engine, not by the language model — so a finding cannot be invented by the model on its own. The model proposes scenarios; the engine decides what they hit.
